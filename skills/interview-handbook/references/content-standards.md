# Content standards

## Chapter structure (adapt to the job)
Front matter: how to use + box legend + **personalised** reading plan and priority map →
Part I: company/role, **you (1b)** → Part II: foundations of their stack + **"my stack → their
stack" Rosetta chapter (2b)** → Part III: the job's core topics, plus a **"do you actually need X?"**
chapter where relevant → Part IV: system design for *their* product, DevOps, domain →
Part V: coding problems with solutions, technical Q&A with model answers, behavioural (STAR from
`profile/stories.md`), a one-weekend mini project that closes the gaps → Appendices: cheat sheet +
glossary, study resources.
Example of everything: `companies/2026-10-nokat/handbook/`.

## Boxes
`concept` (definitions) · `mental` (mental model) · `task` + `solution` · `pitfall` · `interview`
(what to say: 60–90 s, core idea + one trade-off + one concrete detail + one honest link to own work)
· `keypoint` (takeaways) · `yourwork` (gold: link to a concrete file/ADR in Stefan's repos) ·
`optional` (grey: already demonstrated; reason + evidence link in the title).

## Writing rules
- English only, including examples (translate foreign-language sentences, concept names, terms).
- Inferred company facts are labelled as inferred.
- Every code block runs; every number is recomputed.
- Diagrams in TikZ/pgfplots: architecture, sequences, ER, state machines, curves.
- Repo link macros: one per repo (`\amz{path}{text}` style), plus `\adr{file}{NNNN}`.

## Study resources
YouTube + official docs, verified by web search. If an exact video URL can't be confirmed, link a
YouTube search URL. Tag `[must]/[recommended]/[optional]` (optional = already known). End with a
day-by-day plan.
